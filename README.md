# EDH ライフカウンター

マジック・ザ・ギャザリング コマンダー戦 (EDH) 専用の、Chromebook タブレット向けライフカウンター (PWA)。

**設計方針: ゲーム中に数える値は、すべてメイン画面から 1 タップで増減できる。**
統率者ダメージも毒も統治者も、サブ画面を開かずにその場で操作します。

---

## 使い方 (Chromebook)

### 1. アプリとしてインストールする (推奨・オフライン対応)

Service Worker を使うため、`https://` または `localhost` で配信する必要があります。

**A. GitHub Pages などに置く場合**

このフォルダの中身をそのまま公開すれば動きます (ビルド不要)。
Chromebook の Chrome でその URL を開き、アドレスバー右端の **インストール** アイコン →「インストール」。
一度開けば全ファイルがキャッシュされ、**以降は機内モードでも起動します**。

**B. Chromebook 内で配信する場合 (Linux 環境が有効なとき)**

```bash
cd edh-life-counter && python3 -m http.server 8080
```

Chrome で `http://localhost:8080/` を開いてインストールします。

インストール後はランチャーからアプリとして起動でき、アドレスバーのない全画面で使えます。

### 2. とりあえず試す

`index.html` をファイルアプリからダブルクリックしても起動します (ビルド不要)。
ただしこの `file://` での起動では Service Worker が使えず、ブラウザの設定によっては
値の保存 (localStorage) も効かないことがあるため、常用するなら 1 のインストールを推奨します。

## メイン画面

各プレイヤーのパネルに、以下がすべて並びます。どれも `−` / `＋` を 1 タップで増減できます。

| 項目 | 操作 |
| --- | --- |
| ライフ | `−5` `−` **数値** `＋` `+5` |
| 統率者ダメージ | **座席のミニマップ**上の、その相手の位置にあるチップ (共闘なら A / B の 2 枠) |
| 統率者税 | ミニマップの自分の席 (破線枠) のチップ。1 タップで 2 ずつ |
| 毒 / エネルギー / 経験 / 速度 / 指輪の誘惑 | それぞれのチップ |
| 統治者 | チップをタップした人が統治者になる (全体で 1 人) |
| 昇殿 | チップをタップで ON / OFF |

- `−` `＋` は **長押しで連続増減** します。
- ライフを操作すると、数字の上に **直近の増減量の合計** が浮かびます (`-8` など)。
  続けて押した分は合算され、手が止まって 3 秒経つと消えて次回はまた 0 から数え直します。
  「8 点与えるつもりが今いくつ減らしたか分からない」を防ぐためのものです。
  統率者ダメージによる自動のライフ減少や、「戻す」による復元もここに反映されます。
- 統率者ダメージ欄は、選んだレイアウトと同じ形の **座席のミニマップ** になっています。
  左隣の相手のチップは左に、正面の相手は奥に並ぶので、名前を読まずに位置で狙えます。
  マップは各プレイヤーの視点に合わせて向きを補正してあるため、**どの席から見ても「左の人は左」** です。
  破線で囲まれたマスが自分の席で、そこに統率者税が入ります。
  マスは等幅・等間隔に整えてあり (席の広さの比までは真似しません)、
  マスが狭いときは相手の名前を落として色ドットと数値だけにするので、文字がボタンに重なりません。
  共闘の A / B は、名前が入りきらないときでも必ず表示されます。
- プレイヤー名をタップすると名前を変更できます。
- 統率者ダメージ 21 以上 / 毒 10 以上 / ライフ 0 以下になると、パネルが暗くなり該当チップが赤くなります。

画面上部のバーには、**現在時刻・経過時間・スタート/一時停止・タイマーリセット・戻す (取り消し)・履歴・設定・リセット** が並びます。

## 設定

- **プレイヤー人数**: 2〜6 人
- **初期ライフ**: 20 / 25 / 30 / 40 / 50 または任意の数値
- **メイン画面レイアウト**: 座席の形に合わせて選べます。それぞれ左右 / 上下を反転した対のパターンを用意してあります
  - **3 人**: 「左1人 / 右2人」「右1人 / 左2人」「手前1人 / 奥2人」「奥1人 / 手前2人」
  - **5 人**: 「左1人 / 右4人」「右1人 / 左4人」(縦長の1人＋2×2 のグリッド)
  - **2 / 4 / 6 人**: 手前・奥で向き合う配置、テーブルを囲む配置、全員同じ向きの格子
  - 横の席は 90° 回転して表示され、その席のプレイヤーから見て正しい向きになります
  - 設定のプレビューに出る青い帯は、**そのプレイヤーが座る側**を表します
- **プレイヤー**: 名前・色・統率者の数 (共闘は「共闘2」を選択)
- **表示するカウンター**: 使わないカウンターを隠すと、残りのボタンが大きくなります
- **統率者ダメージでライフを自動増減**: 統率者ダメージ +1 でライフが自動的に −1 されます (既定 ON)
- **画面を常にオンにする**: Screen Wake Lock でゲーム中の消灯を防ぎます (既定 ON)

すべての値と設定は自動保存され、アプリを閉じても続きから再開できます。

## 画面サイズへの追従

固定ピクセルではなく **コンテナクエリ単位 (`cqmin`)** で組んであるため、
パネルの大きさに応じて文字とボタンが自動で拡大縮小します。
HP Chromebook x2 11 (2160×1440) でも、1280×800 クラスの Chromebook でも同じレイアウトで動作します。

パネルが横長になる配置 (2 人の上下対面、囲みレイアウトの左右席など) では、
ライフ / カウンター / 統率者ダメージを自動的に横 3 列に組み替えて、横幅を無駄なく使います。
このときカウンター列はチップの幅ぴったりに詰めて統率者ダメージ側へ寄せ、
浮いた横幅はライフ欄に回すので、横向きの席でもライフの数字が大きく表示されます。

ライフの数字は枠に合わせて自動で拡大縮小します。1 桁なら大きく、
`100` や `-12` のような 3 桁になると枠に収まるまで縮むので、桁あふれで欠けることがありません。

座席マップのチップは、1 マスの実寸を毎回測って詰め方を 3 段階で切り替えます。
名前が入る幅があれば名前を出し、足りなければ色ドットと数値だけにし、
さらに狭ければボタンと文字も一段小さくします。判定に使う値はモードによって変わらないので、
表示が交互に切り替わり続けることはありません。

## ファイル構成

```
index.html              画面の骨組み
styles.css              レイアウトとスケーリング
app.js                  状態管理・操作・履歴・設定 (依存ライブラリなし)
sw.js                   オフライン用 Service Worker
manifest.webmanifest    PWA 設定
icons/                  アプリアイコン
```

ファイルを更新したら `sw.js` の `CACHE` の値 (`edh-life-counter-v6`) を上げてください。
古いキャッシュが破棄され、次回起動時に新しいファイルが読み込まれます。
